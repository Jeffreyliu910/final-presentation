Medical Skill Hub｜7 分钟讲述顺序
【生成内容：依据 grade_scale.md 与 Topic 1、3–6 整合】

总节奏：5 分钟讲述 + 2 分钟 Topic 2 Demo = 7 分钟
叙事主线：临床门槛 → 技术差异 → 现场证明 → 产业价值 → 商业复制 → 投资逻辑 → 赛后落地

01｜0:00–0:20｜开场定位｜20 秒
任务：一句话讲清“是什么、解决什么、为什么不同”。
核心句：Medical Skill Hub 让医疗大模型从“检索指南”走向“执行指南”。
转场：为什么现有医疗问答不能直接进入临床？因为医生要回答三个更难的问题。

02｜0:20–1:05｜真实临床门槛｜45 秒
任务：用“不可信、不精准、不透明”定义真实产业问题。
核心句：医生需要的不只是答案，而是患者证据、适用指南与可复核推理链。
转场：所以我们没有继续做更大的知识库，而是改变了指南进入大模型的方式。

03｜1:05–2:00｜核心创新｜55 秒
任务：清楚对比传统 RAG 与 Guideline-as-Skill，覆盖创新性与壁垒。
核心句：传统 RAG 回答“指南里有没有”，Medical Skill Hub 回答“当前患者该执行哪条推荐”。
必须守住的表述边界：只说“理念与 WHO SMART Guidelines 对齐”，不说“符合/基于其标准实现”。
转场：下面不再讲架构，用一条病例证明核心闭环。

04｜2:00–4:00｜Topic 2 现场 Demo｜120 秒
唯一目标：病例 → 患者证据 → Skill 调用 → 带指南来源的 Top-K 鉴别诊断。
0–15 秒：打开预载、脱敏病例。
15–35 秒：一键提交任务，不登录、不配置、不输入长 Prompt。
35–60 秒：展示患者证据抽取与原文定位。
60–85 秒：展示 Skill 路由、适用条件与指南条目。
85–115 秒：停在结果页，展示 Top-K、支持/反对证据、来源与下一步建议。
115–120 秒：说明医生确认边界，报本次实际耗时。
故障切换：点击后 3 秒无响应就切同一病例的离线录屏。
固定口令：“为保证时间，我切到同一病例的离线记录，继续展示结果和证据链。”
转场：刚才证明的不是模型会回答，而是结果能回到患者证据和指南依据。

05｜4:00–4:45｜产业价值｜45 秒
任务：把 Demo 映射到医院、医生、信息化平台三类价值。
核心句：交付物从一次“模型回答”，变成可以持续交付和验证的临床能力。
指标边界：只报真实已有数据；建议口径为 Top-K、依据覆盖/可追溯、单病例耗时、指南转 Skill 周期。
转场：当 Clinical Skill 成为最小交付单元，增长就不再依赖一次性项目。

06｜4:45–5:35｜商业计划与成长｜50 秒
任务：讲清谁付费、买什么、如何获客、如何复制。
核心句：先做成一个标杆科室，再用“一个平台 + 多个 Skill Pack”复制。
获客链：临床专家 → 标杆科室 → 标杆医院 → 同类医院 → HIS/EMR/CDSS 渠道。
收入链：平台授权 + Skill Pack + 部署集成 + 持续更新/API/SDK/Runtime。
转场：所以融资不是堆算力，而是连续跨过产品、临床、商业三次验证。

07｜5:35–6:20｜投资价值｜45 秒
任务：把融资额、跑道、里程碑和风险降低绑定。
核心句：拟融资 300–500 万元，支持 12–18 个月，换来“产品可用、临床有效、商业可复制”。
上台前确认：融资金额与期限必须仍代表团队真实计划；若未确认，应删除金额，只保留里程碑。
转场：赛后 6 个月，我们用具体交付物启动这三次验证。

08｜6:20–7:00｜落地计划与收束｜40 秒
任务：给出 3–6 个月可核验计划，并明确合作诉求。
0–1 月：Medical Skill Hub V1.0。
1–2 月：Clinical Evaluation + V1.1。
2–3 月：消化内科科室试点。
3–4 月：标准化私有部署方案。
4–6 月：至少一项持续试点、联合研发或产品集成合作。
合作诉求：试点医院/临床医生；HIS/EMR/CDSS 集成伙伴；产业与投资资源。
结束句：让每一条权威指南，成为 AI 可执行、医生可验证的临床能力。谢谢各位评委。

彩排红线
1. 总时长超过 7:00 时，不删结尾；先压缩第 2、5 页各 5 秒。
2. Demo 必须提前预载病例，并准备同病例、同路径、同结果的离线录屏。
3. 所有数字必须有样本量、指标定义和来源；没有实测值时不要临场补数。
4. “辅助临床决策，不替代医生最终诊断”至少在 Demo 结果页口头讲一次。
5. 若团队不能承诺当地注册、落户或驻场，不要在台上承诺；保持当前“试点/联合研发/产品集成”的可执行表述。
